# WebNovel Backend Starter

Produces a standalone `backend/` Spring Boot app (its own Maven project, not a
monorepo module — frontend and backend are independently configured and
deployed, per `PROJECT SPEC.md` §4.1.1) matching the stack and layering
committed to in `PROJECT SPEC.md` §4.2 and `WebNovel Platform SRS v2.txt` §2.2:
Spring Boot 3.5.16 on Java 21, layered controller → service → repository,
PostgreSQL as the single source of truth (no Redis), Flyway migrations, JWT
auth with role-based access control, and the REST contract in §10 served under
`/api/v1`.

> **Status: this is a design blueprint, not an executed scaffold.** Unlike the
> `frontend-starter` skill (which was run end-to-end), **no code here has been
> built or run yet** — it was written from the spec plus current-as-of-July-2026
> library research so a future agent can execute it. Treat the versions and
> commands as the intended target; when you actually run them, trust the real
> tool output over this document and correct anything that drifted (see
> Gotchas). Verify each phase with `./mvnw test` as you go, rather than assuming
> the whole thing compiles.

## Ground truth, in priority order

1. **`webnovel platform erd v2.mmd`** and **`V1  init schema.sql`** — the
   **authoritative schema**. The provided SQL file *is* the Flyway `V1`
   migration (see §7); entities mirror it exactly. Do not redesign tables.
2. **`PROJECT SPEC.md`** — functional requirements (§6), core algorithms (§9),
   API contract (§10), configurable parameters (§14). Every endpoint, status
   code, enum value, and business rule traces back here.
3. **`PROJECT SPEC.md` §4.1.1** — decisions the frontend already locked in that
   the backend **must** match (camelCase JSON, denormalized read-model fields,
   409 bodies with `reason`, the `kind`/`ban` discriminators, `/authors/me`,
   `BOOKMARK`, etc.). These are contract, not suggestions — the frontend is
   already built against them.

## Architectural decisions this skill locks in

- **Layered, business-rules-in-services.** Controllers do HTTP + validation +
  DTO mapping only. All rules (access control, fee split, discussion caps, view
  dedup) live in `service/` as independently unit-testable methods (§9,
  `PROJECT SPEC.md` §7.5). A controller never calls a repository directly.
- **camelCase JSON, snake_case DB.** Jackson serializes Java fields as
  camelCase (`bookId`, `isPremium`, `authorUsername`) — this is the wire
  contract the frontend is already built against (§4.1.1). Entities map to
  snake_case columns with `@Column(name = "...")` / Hibernate's implicit
  snake_case naming. **DTOs, never entities, cross the controller boundary.**
- **DTOs are Java `record`s.** Request records carry Jakarta validation
  annotations; response records are assembled in services (or lightweight
  mappers), including the denormalized read-model fields §4.1.1 requires
  (`authorUsername`, `chapterCount`, `likedByMe`, etc.) — populate these via
  JPQL projections/joins, not by leaking entities.
- **JWT: stateless access token, stateful (revocable, rotating) refresh
  token.** FR-1.3 requires refresh rotation and server-side revocation, so
  refresh tokens are **persisted** (`refresh_tokens` table, migration `V2`) and
  rotated on every `/auth/refresh`; logout deletes them. The short-lived access
  token is verified statelessly on every request by the JWT filter — this
  *is* the "token verification" path (`GET /users/me` succeeds ⇔ token valid).
- **Suspended/banned users blocked at the auth filter**, not the controller
  (FR-1.4) — the filter rejects a valid token whose user `status` is
  `suspended`/`banned` with 403.
- **Machine-readable errors.** One `@RestControllerAdvice` returns a consistent
  `ApiError` body with a stable `code` (enum) the frontend switches on — e.g.
  403 `no_subscription`/`expired_subscription` (FR-4.4), 409
  `already_has_thread`/`book_window_full` (§4.1.1). Never a bare 500 or a raw
  stack trace.
- **API versioning by path prefix `/api/v1`.** Centralized via
  `server.servlet.context-path` **is not used**; instead every controller is
  mapped under `/api/v1/...` (a shared base constant or a
  `@RequestMapping("/api/v1")` on each controller). This keeps the version in
  the routes exactly as §10 lists them and leaves room for a `v2` package later.
- **Postgres-only concurrency primitives.** The debate-thread 10-per-5-days cap
  uses `pg_advisory_xact_lock(book_id)` inside the creating transaction (§9.6);
  view-dedup is an indexed `EXISTS` query (§9.2). No Redis, no app-level locks.

## 1. Generate the project (Spring Initializr)

Run from the repo root (creates a standalone `backend/` Maven project):

```bash
curl -s https://start.spring.io/starter.tgz \
  -d type=maven-project -d language=java -d javaVersion=21 \
  -d bootVersion=3.5.16 \
  -d groupId=com.webnovel -d artifactId=backend -d name=backend \
  -d packageName=com.webnovel \
  -d dependencies=web,security,data-jpa,validation,postgresql,flyway,docker-compose,actuator \
  -o backend.tgz && mkdir -p backend && tar -xzf backend.tgz -C backend && rm backend.tgz

**JJWT** artifacts (above), `flyway-database-postgresql`,

`org.testcontainers:junit-jupiter`. `spring-boot-starter-test` (JUnit 5,
Mockito, AssertJ, MockMvc) and `spring-security-test` come with the Initializr
selection.

Set `<java.version>21</java.version>` and pin the springdoc/testcontainers
versions via the Spring Boot BOM where managed.

## 3. Flyway migrations

- **`V1__init_schema.sql`**: copy the repo's `V1  init schema.sql` verbatim into
  `src/main/resources/db/migration/V1__init_schema.sql` (rename to the Flyway
  `V1__` convention — double underscore). It is already the authoritative,
  Postgres-targeted schema for every ERD table. Do not edit it to "fix" naming;
  the entities adapt to it, not the reverse.
- **`V2__refresh_tokens.sql`**: the one table the ERD omits but auth needs —
  server-side revocable refresh tokens (FR-1.3):

```sql
CREATE TABLE refresh_tokens (
    id           BIGSERIAL PRIMARY KEY,
    user_id      BIGINT NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    token_hash   VARCHAR(255) NOT NULL UNIQUE,   -- store a SHA-256 hash, never the raw token
    expires_at   TIMESTAMPTZ NOT NULL,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_refresh_tokens_user ON refresh_tokens(user_id);
```

Later domain additions from §4.1.1 (e.g. the `BOOKMARK (reader_id, book_id)`
table, unique per pair) each get their own forward migration `V3__...`,
`V4__...` — **never edit an applied migration**; Flyway checksums them.

`ddl-auto: validate` means the moment an entity and the schema disagree the app
fails to start with a clear mismatch — the intended safety net.

## 4. Security & JWT (the auth vertical slice)

This is the worked example every other feature copies. It implements
`/api/v1/auth/register|login|refresh|logout` (§10.1) + `GET /users/me` (§10.2),
which doubles as the frontend's boot-time token verification.

**`JwtService`** — signs a short-lived access token carrying `sub = userId`,
`role`, `status`; parses/validates it; and mints opaque refresh tokens (a random
string; only its SHA-256 hash is stored):

```java
@Service
public class JwtService {
    private final SecretKey key;
    private final JwtProperties props;

    public JwtService(JwtProperties props) {
        this.props = props;
        this.key = Keys.hmacShaKeyFor(props.secret().getBytes(StandardCharsets.UTF_8)); // secret ≥ 32 bytes
    }

    public String generateAccessToken(User user) {
        Instant now = Instant.now();
        return Jwts.builder()
            .subject(String.valueOf(user.getId()))
            .claim("role", user.getRole().name())
            .claim("status", user.getStatus().name())
            .issuedAt(Date.from(now))
            .expiration(Date.from(now.plus(props.accessTtl())))
            .signWith(key)
            .compact();
    }

    public Jws<Claims> parse(String token) {          // throws JwtException on invalid/expired
        return Jwts.parser().verifyWith(key).build().parseSignedClaims(token);
    }
}
```

**`JwtAuthenticationFilter`** (`OncePerRequestFilter`) — extracts the bearer
token, validates it, loads the principal, and **rejects suspended/banned users
here** (FR-1.4) before the request reaches any controller:

```java
@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    private final JwtService jwtService;
    private final AppUserDetailsService userDetailsService;

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        String header = req.getHeader(HttpHeaders.AUTHORIZATION);
        if (header != null && header.startsWith("Bearer ")) {
            try {
                Claims claims = jwtService.parse(header.substring(7)).getPayload();
                var principal = userDetailsService.loadById(Long.valueOf(claims.getSubject()));
                if (principal.isBlocked()) {          // suspended/banned → 403, not authenticated
                    res.sendError(HttpServletResponse.SC_FORBIDDEN);
                    return;
                }
                var auth = new UsernamePasswordAuthenticationToken(principal, null, principal.getAuthorities());
                auth.setDetails(new WebAuthenticationDetailsSource().buildDetails(req));
                SecurityContextHolder.getContext().setAuthentication(auth);
            } catch (JwtException | IllegalArgumentException ignored) {
                // leave unauthenticated → entry point returns 401 if the route requires auth
            }
        }
        chain.doFilter(req, res);
    }
}
```

**`SecurityConfig`** — stateless, method security on, public routes whitelisted,
BCrypt, CORS from config:

```java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity                    // enables @PreAuthorize("hasRole('ADMIN')") on controllers
@RequiredArgsConstructor
public class SecurityConfig {
    private final JwtAuthenticationFilter jwtFilter;
    private final RestAuthEntryPoint authEntryPoint;

    @Bean SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.csrf(AbstractHttpConfigurer::disable)
            .cors(Customizer.withDefaults())
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/v1/auth/**").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/v1/books/**", "/api/v1/authors/**").permitAll()
                .requestMatchers("/swagger-ui/**", "/v3/api-docs/**", "/actuator/health").permitAll()
                .anyRequest().authenticated())
            .exceptionHandling(e -> e.authenticationEntryPoint(authEntryPoint))
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    @Bean PasswordEncoder passwordEncoder() { return new BCryptPasswordEncoder(); }
    @Bean AuthenticationManager authManager(AuthenticationConfiguration c) throws Exception { return c.getAuthenticationManager(); }
}
```

> Public GET whitelisting is coarse here; endpoints that are *access-controlled*
> rather than *public* (e.g. `GET /chapters/{id}`, which is servable to anyone
> for a free book but 403s for a premium one, FR-4.x) stay `authenticated()`-
> optional and enforce access in the **service** via `AccessControlService`
> (§9.1) — the filter chain is not where premium gating lives.

**`AuthService` / `AuthController`** — register creates `USER` (`role=reader`,
`status=approved`, bcrypt hash, FR-1.2) and, for author applications, the
pending flow; login authenticates and issues both tokens; refresh **rotates**
(validate stored hash → delete → issue new pair, FR-1.3); logout deletes the
stored refresh token. Response shape matches the frontend
(`{ accessToken, refreshToken, user }`, camelCase — §4.1.1, `frontend/src/types/auth.ts`).
All four auth endpoints are `POST /api/v1/auth/...`.

## 5. Error handling & request validation

**Request validation**: every write endpoint takes a `record` request DTO with
Jakarta constraints and `@Valid`; messages come from `messages*.properties` via
`{key}` so they localize:

```java
public record RegisterRequest(
    @NotBlank @Size(min = 3, max = 50) String username,
    @NotBlank @Email String email,
    @NotBlank @Size(min = 8, max = 100) String password) {}
```

**Global handler** — one `@RestControllerAdvice` maps exceptions to a stable
`ApiError` with a machine-readable `code` (the frontend switches on `code`, and
on `reason`-style bodies where §4.1.1 calls for them):

```java
public record ApiError(String code, String message, Map<String,String> fieldErrors, Instant timestamp) {}

public enum ErrorCode {
    VALIDATION_FAILED, UNAUTHORIZED, FORBIDDEN, NOT_FOUND, CONFLICT,
    NO_SUBSCRIPTION, EXPIRED_SUBSCRIPTION,        // FR-4.4 (403 body)
    ALREADY_HAS_THREAD, BOOK_WINDOW_FULL,         // FR-9.1 / FR-9.2 (409 body, §4.1.1)
    DUPLICATE_PAYMENT, INSUFFICIENT_BALANCE, INTERNAL_ERROR
}
```

```java
@RestControllerAdvice
@RequiredArgsConstructor
public class GlobalExceptionHandler {
    private final MessageSource messages;

    @ExceptionHandler(MethodArgumentNotValidException.class)
    ResponseEntity<ApiError> onValidation(MethodArgumentNotValidException ex, Locale locale) {
        var fields = ex.getBindingResult().getFieldErrors().stream()
            .collect(Collectors.toMap(FieldError::getField, FieldError::getDefaultMessage, (a,b) -> a));
        return build(HttpStatus.BAD_REQUEST, ErrorCode.VALIDATION_FAILED, "error.validation", locale, fields);
    }

    @ExceptionHandler(ApiException.class)       // carries its own status + ErrorCode + message key
    ResponseEntity<ApiError> onApi(ApiException ex, Locale locale) {
        return build(ex.getStatus(), ex.getCode(), ex.getMessageKey(), locale, ex.getExtraFields());
    }

    // AccessDeniedException → 403 FORBIDDEN, AuthenticationException → 401, fallback → 500 INTERNAL_ERROR
}
```

`AccessControlService` throwing a `ForbiddenException(ErrorCode.NO_SUBSCRIPTION,
authorId)` (FR-4.4) surfaces as a 403 whose body names the author to subscribe
to — exactly what the frontend's 403 subscribe-redirect needs. Debate-thread
creation throws `ConflictException(ALREADY_HAS_THREAD | BOOK_WINDOW_FULL)` → 409
with the `reason` the frontend renders the right message from.

## 6. Internationalization (English / Myanmar)

Stateless, header-driven — matches a REST API with a separate SPA that already
persists the user's language choice and can send `Accept-Language: my`.

**`WebI18nConfig`**:

```java
@Configuration
public class WebI18nConfig {
    @Bean LocaleResolver localeResolver() {
        var r = new AcceptHeaderLocaleResolver();
        r.setSupportedLocales(List.of(Locale.ENGLISH, Locale.of("my")));
        r.setDefaultLocale(Locale.ENGLISH);
        return r;
    }
    @Bean MessageSource messageSource() {
        var ms = new ReloadableResourceBundleMessageSource();
        ms.setBasename("classpath:messages");
        ms.setDefaultEncoding("UTF-8");
        ms.setDefaultLocale(Locale.ENGLISH);
        return ms;
    }
    @Bean LocalValidatorFactoryBean getValidator(MessageSource ms) {   // localize @Valid messages
        var v = new LocalValidatorFactoryBean();
        v.setValidationMessageSource(ms);
        return v;
    }
}
```

`messages_en.properties` / `messages_my.properties` (UTF-8; Burmese in the `_my`
file) carry both validation and error/business keys — e.g.
`error.validation`, `error.no_subscription`, `error.already_has_thread`,
`validation.username.size`. The `{validation.username.size}` reference in a
constraint annotation resolves per request locale. Keep the two files key-for-key
in sync in the same change (the frontend enforces the same EN/MY parity rule).

## 7. Entities, repositories, services, controllers (the layered pattern)

Every domain (books, chapters, subscriptions, payments, earnings, debates,
engagement, moderation, admin) is one vertical slice shaped like `auth`:

- **`domain/entity/`** — a JPA `@Entity` per ERD table, columns mapped to the
  snake_case schema (`@Table(name="chapters")`, `@Column(name="unique_view_count")`).
  Enums stored as `@Enumerated(EnumType.STRING)` matching the SQL `CHECK` values
  (`reader`, `hobbyist_author`, …). `@Version` optimistic locking on rows with
  denormalized counters that concurrent requests mutate (`available_balance`,
  counts) where a lost update would matter. Money is `BigDecimal`
  (`NUMERIC(…)`), timestamps `Instant`/`OffsetDateTime` (`TIMESTAMPTZ`).
- **`repository/`** — Spring Data JPA interfaces. Custom queries for the
  algorithms: `existsRecentView(chapterId, sessionId, deviceFingerprint, since)`
  (§9.2, hits the `idx_chapter_views_dedup` index), `findActiveSubscription(readerId, authorId)`
  (§9.1), `countByBookSince(bookId, since)` under advisory lock (§9.6),
  `incrementUniqueViewCount(chapterId)` as a `@Modifying` update. Read-model
  projections supply the denormalized display fields (`authorUsername`,
  `chapterCount`, `likedByMe`) via JPQL constructor expressions or interface
  projections — never by serializing entities.
- **`service/`** — the business rules and the §9 algorithms, `@Transactional`
  where multiple writes must be atomic (payment approval → earning credit →
  balance increment, FR-7.1/§9.4, is one transaction). Admin-only operations
  are additionally guarded with `@PreAuthorize("hasRole('ADMIN')")` (method
  security, `PROJECT SPEC.md` §5).
- **`dto/`** — request records (validated) and response records (assembled),
  grouped by domain. Response records include §4.1.1's denormalized fields.
- **`controller/`** — thin `@RestController`s, all under `/api/v1`, one per
  domain area, methods 1:1 with the §10 endpoint table. They validate, delegate
  to a service, map to a response DTO, set the status code. No business logic.

Build order (from `PROJECT SPEC.md` §15, dependency-ordered): **auth →
books/chapters → access control → hobbyist review → payments/earnings →
engagement → debate engine → moderation/admin → NFR polish → deploy.** Ship each
slice with its tests before starting the next.

## 8. Testing

Two layers, both required (`PROJECT SPEC.md` §15 phase 10):

**Unit tests (JUnit 5 + Mockito)** — the §9 algorithms as pure service methods
with mocked repositories, no Spring context. These are the flagship deliverable;
cover the branch table of each algorithm:

- `AccessControlServiceTest` (§9.1): free book → allow; premium + no user →
  `NO_SUBSCRIPTION`; premium + admin/own-author → allow; active sub → allow;
  expired sub → `EXPIRED_SUBSCRIPTION`; no sub → `NO_SUBSCRIPTION`.
- `ViewTrackingServiceTest` (§9.2): recent view exists → `isUnique=false`, no
  counter bump; none → `isUnique=true`, counter incremented.
- `DebateThreadServiceTest` (§9.6): existing thread by creator → reject
  `ALREADY_HAS_THREAD`; ≥10 in window → reject `BOOK_WINDOW_FULL`; else created.
- `PaymentApprovalServiceTest` (§9.4): approval credits exactly one
  `AUTHOR_EARNING` with the right fee split and increments balance once.

```java
@ExtendWith(MockitoExtension.class)
class AccessControlServiceTest {
    @Mock SubscriptionRepository subscriptions;
    @InjectMocks AccessControlService service;

    @Test void freeBook_allowsAnonymous() {
        var chapter = chapterInBook(book -> book.setPremium(false));
        assertThatCode(() -> service.assertCanAccess(null, chapter)).doesNotThrowAnyException();
    }
    @Test void premiumBook_noSubscription_throwsNoSubscription() {
        var chapter = chapterInBook(book -> book.setPremium(true));
        when(subscriptions.findActive(1L, chapter.getBook().getAuthorId())).thenReturn(Optional.empty());
        assertThatThrownBy(() -> service.assertCanAccess(reader(1L), chapter))
            .isInstanceOf(ForbiddenException.class)
            .extracting("code").isEqualTo(ErrorCode.NO_SUBSCRIPTION);
    }
}
```

**Integration tests (Testcontainers + real Postgres + real Flyway)** — a shared
base spins up one container per test run; `@ServiceConnection` wires the
datasource, and Flyway runs `V1`/`V2` against it, so tests exercise real JPA
mappings, real constraints (the `UNIQUE (book_id, creator_id)` reject, the
payment-dedup index), and real advisory locks — none of which H2 reproduces:

```java
@SpringBootTest
@AutoConfigureMockMvc
@Testcontainers
abstract class AbstractIntegrationTest {
    @Container @ServiceConnection
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:16");
    @Autowired protected MockMvc mvc;
}
```

`AuthControllerIT extends AbstractIntegrationTest` drives the real contract:
`POST /register` → `POST /login` (asserts `accessToken`/`refreshToken`/`user` in
camelCase) → `GET /users/me` with the bearer token (token-verification path) →
`POST /refresh` rotates → old refresh token is now rejected → `POST /logout`
revokes. At least one access-control IT should assert a premium chapter returns
403 `no_subscription` for a non-subscriber and 200 after an approved payment.

Run with `./mvnw test`. Requires a running Docker daemon for the integration
layer; keep unit tests runnable without Docker so `./mvnw test -Dtest='*Test'`
stays fast.

## Gotchas

- **`ddl-auto` must be `validate`, never `update`/`create`.** Flyway is the
  single schema authority (`PROJECT SPEC.md` §7.4). `update` would let Hibernate
  silently diverge the DB from the migrations and mask a broken entity mapping.
- **`flyway-database-postgresql` is a separate dependency** on Flyway 10+/Spring
  Boot 3.5 — `flyway-core` alone fails at startup with "no Flyway database
  support" against Postgres.
- **JJWT `impl` and `jackson` are `runtime` scope**, `api` is compile — mixing
  scopes (or importing internal `io.jsonwebtoken.impl.*` classes) is the classic
  JJWT setup break. Use the 0.12.x builder API (`.subject()`, `.signWith(key)`,
  `.verifyWith(key).build().parseSignedClaims(...)`) — pre-0.12 tutorials show
  the removed `setSubject`/`parseClaimsJws` API.
- **The JWT secret must be ≥ 32 bytes** for `Keys.hmacShaKeyFor` (HS256) or it
  throws `WeakKeyException` at boot. Keep it in `APP_JWT_SECRET`, never in a
  committed file (spec §7.3).
- **Don't confuse the DB column casing with the JSON casing.** The schema is
  snake_case; the wire format is camelCase (§4.1.1). Entities bridge them with
  `@Column(name=...)`; DTOs are already camelCase. If you ever see snake_case in
  an API response, an entity leaked past the controller — fix the mapping, don't
  add a Jackson naming strategy that breaks the frontend contract.
- **Premium gating is not a filter-chain rule.** A free book's chapter is
  readable anonymously; a premium book's is not (FR-4.1/4.2). That decision
  needs the book row, so it lives in `AccessControlService`, invoked by
  `ChapterService` — not in `SecurityConfig`. Whitelisting `GET /chapters/**` as
  public and calling it done would leak premium content.
- **The debate 10-per-5-days check needs the advisory lock inside the
  transaction** (`pg_advisory_xact_lock`, §9.6), or two concurrent creates both
  pass the count and exceed the cap. The `UNIQUE (book_id, creator_id)` handles
  one-per-reader at the DB level; the *window* cap is the race that needs the
  lock. This is a Postgres-only mechanism — a reason H2 can't stand in for the
  integration tests.
- **`open-in-view: false`** is set deliberately — it forces you to assemble
  response DTOs (with their joins/projections) inside the transactional service,
  rather than relying on lazy loading during JSON serialization in the
  controller. Expect `LazyInitializationException` if you try to serialize a
  lazy entity association from a controller; that's the guardrail working.
- **Spring Boot 3.5 is OSS-EOL as of 2026-06-30.** The spec pins 3.5.16, so use
  it, but say so in the README — a genuine production deployment would schedule a
  Spring Boot 4.x upgrade rather than run an unpatched branch.
- **`messages_my.properties` must be UTF-8** and every key present in
  `messages_en.properties` — a missing `_my` key silently falls back to English
  mid-response, which reads as a half-translated error.

## Extending this starter

Each remaining domain (`PROJECT SPEC.md` §6, FR-2 … FR-13) is a new vertical
slice shaped like `auth`: entities (mirroring the ERD), repository (with the
custom queries its algorithms need), service (business rules, `@Transactional`,
`@PreAuthorize` for admin ops), request/response DTO records, and a thin
controller under `/api/v1` matching the §10 endpoint table. Reuse
`ApiError`/`ErrorCode`, the JWT principal, and the i18n message keys rather than
inventing per-feature variants. Honor every §4.1.1 decision (the `kind`/`ban`
discriminators, `/authors/me` with wallet fields, denormalized read-model
fields, `BOOKMARK`, `POST /chapters/{id}/publish` `scheduledFor`, client-supplied
view-dedup signals) — the frontend is already built against them, so they are
contract. Scheduled jobs (renewal reminders FR-6.6, scheduled-chapter
auto-publish FR-2.6) are Spring `@Scheduled` methods guarded by a persisted flag
(`reminder_sent`), single-instance-safe per §4.4.
